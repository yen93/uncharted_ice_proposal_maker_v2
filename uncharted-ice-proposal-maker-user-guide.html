Uncharted Ice Proposal Maker

User Guide

The Uncharted Ice Proposal Maker turns a salesperson's demo-call notes into a polished, client-tailored "Uncharted Ice" sales proposal — a finished Google Slides deck — automatically. Claude reads the notes, personalises the right slides to the client while keeping the deck's professional design and branding, swaps in the client's logo, and emails the finished proposal to the reviewer for a final check before it goes out.

Who This Guide Is For

The My Adventure Group sales and operations team — anyone who runs demo calls and needs an Uncharted Ice proposal built for a client, and the reviewer who checks each proposal before it is sent. You do not need any technical or design skills to benefit from it; the system does the building, and a person does the final review.

What It Needs From You

To build a good proposal, the system needs the demo-call notes and, optionally, a little extra context:

  • The demo-call notes as a Google Drive file — a clear photo, scan, or PDF of the completed notes page. The clearer and more legible the handwriting, the better the result (especially the client's name, the key themes, the investment figures, and the "Add Bonus Value" ticks).
  • Optional extra notes — any context that isn't written on the page but should shape the proposal (for example, "emphasise rebuilding trust across a team that rarely meets in person").

Note: the exact step-by-step for submitting a request is still being finalised. This guide will be updated with those instructions once the submission method is set. What follows describes what the system does and what to expect from it.

What You Get

For each request, the system creates a new folder in the Proposals Drive named after the client, containing everything for that proposal:

  • The original demo-notes file.
  • A plain-text transcription of the notes.
  • The finished, client-tailored proposal deck, named "<Client> - Uncharted Ice Proposal".

What to Expect

  • A tailored deck, not a generic one. The cover, the introduction, the learning objectives, the program components, the "what it is / how it works" slides, and the investment slide are all personalised to the client. The slides that are already perfect are left exactly as designed.
  • The design is preserved. The deck's exact look — fonts, colours, and the signature single-word highlights (like the highlighted word in "YOUR INVESTMENT") — is kept intact. Only the client-specific wording changes.
  • Only the relevant slides. The general "program framework" slide is removed, and only the bonus slides that were actually offered on the notes (for example the Debrief Call or the Executive X invitation) are kept.
  • The client's logo is added. The system replaces the placeholder logo on the cover and footers with the client's logo automatically.
  • Always a draft for review. Every proposal is flagged for a human to check before it is sent to a client. It is emailed to the reviewer, never straight to the client.
  • Turnaround. Requests are processed automatically on an hourly schedule (or on demand), so a proposal is typically ready within the hour.

Known Limitations

Being upfront about what the system does not do saves everyone time:

  • It produces a review draft, not a send-ready final. A person must review each proposal before it goes to the client.
  • The logo is a best guess. It is found automatically and can be the wrong variant, colour, or a low-resolution version — always confirm it looks right on the cover and footers.
  • It relies on legible notes. The client name, bonus ticks, figures, and dates are read from the notes page; very messy handwriting can be misread. If the client name can't be read at all, the request is flagged as an error rather than guessing.
  • It does not send anything to the client. It emails the reviewer only.
  • It doesn't proofread itself visually on automated runs. A quick human look is expected — that's what the review step is for.

How It Was Built (Architecture & Tech Stack)

Behind the scenes, the proposal is assembled by Claude working through the same steps a person would, in order:

  • Request queue — each request records a link to the demo-notes file (and any extra notes) so the system knows what to build.
  • Claude Code cloud routine — an automated agent that runs on an hourly schedule (and can also be run on demand), picking up any requests that haven't been built yet.
  • Transcribe — Claude reads the notes file directly and writes them out as text, including which bonuses were ticked.
  • Build the deck — Claude creates the client's Drive folder, moves the notes in, copies the master proposal template, and tailors the client slides in place so the deck's exact design and highlights are preserved.
  • Finish and hand off — Claude removes the slides that don't apply, keeps only the offered bonuses, swaps in the client's logo, emails the reviewer, and marks the request done.

Tech stack, in plain terms:

  • Claude Code — the automation's "brain", including its cloud Routines feature that runs the job unattended.
  • Google Slides, Google Drive & Gmail — where the deck is built, stored, and the notification is sent from.
  • Supabase — the small database that holds the request queue.
  • Python helper scripts — a set of small commands Claude uses to perform each Google operation reliably.

Notably, there is no separate "AI text" service involved — Claude itself reads the notes and writes the tailored wording, so there is one system doing the whole job.

Troubleshooting

  • The proposal hasn't appeared. It may not have been picked up yet (the routine runs hourly), or the notes-file link was missing or unreadable. Check the client's folder in the Proposals Drive and the reviewer's email.
  • The client name is wrong or shows as unknown. The notes were hard to read. Make sure the client's name is written clearly and legibly on the notes page.
  • The logo is wrong, blurry, or missing. The logo is an automatic best guess — replace it by hand on the cover and footer slides.
  • The wrong bonus slides are shown. The "Add Bonus Value" ticks were misread. Keep or remove the bonus slides manually to match what was offered.
  • Figures, dates, or audience details look off. These are transcribed straight from the notes — confirm them against the page and adjust if needed.
